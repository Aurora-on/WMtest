# 防止测试真值参与预测的回归测试

在实验目录运行：

```bash
.venv/bin/python -B -m pytest -p no:cacheprovider tests/test_no_future_leakage.py -q
```

测试调用现有 `dpbench.evaluate.evaluate()`，覆盖 HDF5 读取、检查点加载、
读出器拟合与选择、完整开环推演、评分和预测文件保存。两种模型分别测试：

- 只替换测试轨迹第 6 帧起的图像：随机像素与帧顺序打乱两种方式。
- 替换测试集的全部真实状态、能量、功与耗散标签，包括初始化时刻标签。
- 同时替换未来图像和测试标签。
- 上述修改后，全部潜在轨迹、两种读出器的预测、校准样本及读出参数必须
  逐元素完全一致；标签改变时，评分必须改变。
- 预测、潜在状态、读出参数和评分必须为有限值，不能靠相同 NaN/Inf 通过。
- 改变合法输入（起始图像或后续动作）必须改变预测；更晚的动作不能改变
  已经产生的预测前缀，防止“忽略所有输入也能通过”的无效检查。
- 每次推演只允许编码起始历史一次，并核对实际送入编码器的像素；模型须
  处于 eval 模式，参数和 BatchNorm 等缓冲区不能被评测或校准更新。
- 校准样本必须来自对应 train/val 集，预测轨迹必须来自 test 集。
- 故意将一帧未来图像混入初始历史，要求同一个不变性检查明确报错；这个
  反例由测试临时注入，不修改生产代码。

测试数据、检查点和评测结果全部生成在 pytest 临时目录。使用官方真实
网络架构的固定测试权重；为覆盖动作路径，LeWM 测试权重中默认全零的
AdaLN 条件权重被确定性初始化为非零值。没有重训或修改实验检查点。
篡改数据后，仅在临时检查点中重新绑定该测试数据哈希，模型权重不变；
生产评测的数据哈希校验仍被执行，没有删除或绕过。

**通过意味着这些信息流回归检查通过，不代表正式 12 组检查点已逐一重跑，
也不证明训练集与测试集没有重复/近重复片段。** 后者属于数据内容审计，
需要独立去重与新的保留测试集。当前测试固定在 CPU 确定性设置下，严格
要求位级不变；GPU 后端的数值一致性需要另外验证。
